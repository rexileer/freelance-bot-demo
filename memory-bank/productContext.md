# Product Context

## Problem & Audience
- Freelance лиды и заявки сложно собирать вручную: нужен Telegram-бот, который принимает пользователей, фильтрует заявки по тематикам и продаёт подписки.
- Основные роли: 
  - **Customer** (фрилансер/агентство) — подключается к тематикам и получает заявки.
  - **Operator** — ведёт контент через Django Admin (тексты, кнопки, тарифы, рассылки, каналы, материалы).
  - **Content curator / Parser** — подключает каналы в парсер, чтобы пойманные заявки автоматически появлялись в очереди.

## Value Proposition
- **Глубокая персонализация**: кастомные тексты/кнопки из БД, персональный реферальный трекер, управление категориями прямо в боте.
- **Data single-source**: Django ORM + PostgreSQL, все сущности (Users, Subscription, Tariffs, Bids, Channels) живут в одной схеме.
- **Operational confidence**: каждый сервис упакован в контейнер, одинаковое окружение локально и в проде, команда команд `manage.py start_*`.

## User Journeys (high-level)
1. Пользователь запускает бота → проходит реферальный код → выбирает тематики → покупает тариф (или берёт пробную подписку) → получает заявки и управляет категориями.
2. Оператор создаёт тарифы, тексты, полезные материалы, подтверждает заявки, размечает каналы.
3. Парсер (Telethon) подписан на набор каналов → ловит сообщения → матчинг по ключевым словам → создаёт `Bid` → mailing-воркер рассылает по подписчикам.
